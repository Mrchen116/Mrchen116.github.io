Proactive long-term agent 内部协作设计

Superagent 让工单接住后续消息。Raft 让主 Agent 留在对话里，持续协调子 Agent。

  • Superagent 把工单和来源消息分别交给 Worker，Worker 可以回读原文。原话题里的补充和答复由系统送给 Worker。若收到另一件事，比如「再做一个发布确认页」，Worker 可以按原消息 ID 退回 Router。群里另发的顶层消息走新话题的判断流程。[3] [4]

子 Agent 问了，谁来决定

Superagent · Router 转问

  • 普通技术选择由 Worker 决定。
  • Worker 标明需要用户决定，Router 到对应话题代问，由用户拍板。

Raft · 主 Agent 先判断

  • 已有依据和授权，主 Agent 可以直接答子 Agent。比如用户已确定英文文案。
  • 出现新的产品选择，主 Agent 问用户，再把决定转给子 Agent。

Superagent 按规则主动接下的工单还有一条限制。执行中如果发现目标需要新增产品决定，Worker 会结束这次执行并报告放弃。上图的转问路径适用于用户直接交办的工单。[3] [5] [7]

长期协作中的决策权

Superagent 的 Router 主要在开工前替用户判断该接什么。Raft 的主 Agent 在开工后也能替用户处理已授权的选择。比如团队已约定帮助页和界面文案同步更新，子 Agent 问帮助页要不要改，主 Agent 就能直接答。

如果模型能可靠地理解上下文和授权范围，我更看好 Raft 的分工。用户可以逐步把一类日常决定交给主 Agent，少做一次次重复确认。过去的选择可以作为判断依据，能否代用户拍板仍取决于用户交给它的权限。
